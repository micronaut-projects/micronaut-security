Micronaut Security publishes a Technology Compatibility Kit (TCK), a JUnit test suite that verifies that a api:security.password.PasswordEncoder[] honours the contract of the API. Use it to test your own implementation.

The TCK requires JUnit 6. Add it and the JUnit Platform Suite as test dependencies:

dependency:micronaut-security-password-tck[groupId=io.micronaut.security,scope=test]

dependency:junit-platform-suite[groupId=org.junit.platform,scope=test]

Then create a suite that selects the package of the TCK:

[source,java]
----
import org.junit.platform.suite.api.SelectPackages;
import org.junit.platform.suite.api.Suite;
import org.junit.platform.suite.api.SuiteDisplayName;

@Suite
@SelectPackages("io.micronaut.security.password.tck")
@SuiteDisplayName("My PasswordEncoder TCK")
public class MyPasswordEncoderSuite {
}
----

The tests start an application context and inject the api:security.password.PasswordEncoder[] bean, so the test classpath must contain exactly one.

The parameters of api:security.password.PasswordEncoder[] are constrained with `@NotBlank`, and the TCK verifies that your implementation enforces those constraints. For Micronaut Validation to apply them, compile your implementation with its annotation processor:

dependency:micronaut-validation-processor[groupId=io.micronaut.validation,scope=annotationProcessor]

The TCK verifies that:

* Encoding the same password twice produces different results, and that the result does not contain the password.
* A password matches its encoded value, and a different password does not.
* Case, whitespace and non-ASCII characters are significant, and passwords are not truncated, neither by length nor at a NUL character.
* `encode` and `matches` reject `null`, empty and whitespace-only values with a `ConstraintViolationException`.
* `matches` returns `false` for a malformed or truncated encoded value.
* The encoder is safe for concurrent use.
