https://www.rfc-editor.org/rfc/rfc9106[Argon2id] is a memory-hard password hashing function and the first choice of the https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html[OWASP Password Storage Cheat Sheet]. To use the Bouncy Castle implementation, add the dependency:

dependency:micronaut-security-argon2-bouncycastle[groupId=io.micronaut.security]

The module contributes a api:security.password.PasswordEncoder[] bean implemented with Bouncy Castle. The bean is named `bouncycastle`. Use that name to select it if the application has <<passwordEncoding, more than one encoder>>.

== Encoded passwords

Passwords are encoded in the https://github.com/C2SP/C2SP/blob/main/phc-strings.md[PHC string format]:

[source,text]
----
$argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>
----

`m` is the memory cost in kibibytes, `t` the number of iterations and `p` the degree of parallelism. The salt and the hash are Base64 encoded without padding. A new random salt is generated for every password.

Size the column that stores the encoded password for the longest value your configuration can produce. With the default configuration an encoded password has 97 characters. With the longest salt and hash, and the largest parameters accepted by default, it has less than 200.

== Configuration

include::{includedir}configurationProperties/io.micronaut.security.password.argon2.Argon2PasswordEncoderConfigurationProperties.adoc[]

The defaults are the minimum configuration recommended by OWASP: 19 MiB of memory, two iterations and one degree of parallelism. OWASP lists other configurations that provide the same level of defense and trade CPU for memory. For example, to use 46 MiB of memory and one iteration:

[configuration]
----
micronaut:
  security:
    password:
      argon2:
        memory: 47104
        iterations: 1
----

The application fails to start if the configuration is invalid: the memory must be at least eight times the parallelism, the parallelism must be between 1 and 255, the salt length between 8 and 48 bytes, and the hash length between 12 and 64 bytes. The memory and iterations cannot exceed `max-memory` and `max-iterations`.

=== Choosing parameters

Hashing is deliberately expensive. Measure how long `encode` takes on your production hardware and choose the highest parameters your login latency and concurrency allow.

Each call to `encode` uses the configured memory, while `matches` uses the memory declared in the encoded password. Concurrent logins multiply that amount.

Hashing blocks the calling thread. Do not call the encoder on an event loop thread.

== Verifying passwords encoded with other parameters

A password is always verified with the parameters stored in its encoded value, not with the configured ones. Passwords encoded before you changed the configuration keep matching.

An encoded password does not match if it declares more memory than `max-memory` or more iterations than `max-iterations`. These limits bound the resources a single stored value can consume. If you lower the configured memory or iterations, keep the limits at or above the highest values present in your stored passwords.

Only Argon2id version 19 is supported. Encoded passwords that use Argon2i, Argon2d, version 16, or the optional `keyid` and `data` parameters do not match.

Passwords encoded with other algorithms, such as bcrypt, do not match. To migrate them, keep verifying them with the previous library and encode the password with api:security.password.PasswordEncoder[] the next time the user logs in successfully.
