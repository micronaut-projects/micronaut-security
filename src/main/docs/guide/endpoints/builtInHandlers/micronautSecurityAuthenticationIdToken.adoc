When you set `micronaut.security.authentication=idtoken`, api:security.oauth2.endpoint.token.response.IdTokenLoginHandler[] a bean of type api:security.handlers.LoginHandler[] and api:security.token.jwt.cookie.JwtCookieClearerLogoutHandler[] a bean of type api:security.handlers.LogoutHandler[] are enabled. Additionally, a link:{api}/io/micronaut/security/token/jwt/nimbus/ReactiveJwksSignature.html[ReactiveJwksSignature] bean is registered for the `jwks_uri` of each OpenID provider, so ID tokens issued by the provider can be used as request credentials, and api:security.oauth2.client.IdTokenClaimsValidator[] verifies that they were issued to this client. Only enabled OAuth 2.0 clients are considered. A disabled client contributes no provider metadata and no JWKS, but that removes only its own trust: when several clients share the same OpenID provider, only `IdTokenClaimsValidator` checks that the `aud` claim names an enabled client, so disabling it with `micronaut.security.token.jwt.claims-validators.openid-idtoken: false` lets a token issued to a disabled client authenticate through the signing keys of an enabled sibling. ID token authentication never accepts unsigned JWTs: even when every OAuth 2.0 client is disabled, or none is configured, and therefore no JWKS is registered, a token without a signature is rejected.

The `iss` claim of such a token is matched against the expected issuer of each OpenID client: `micronaut.security.oauth2.clients.*.openid.issuer-identifier` if set, otherwise `micronaut.security.oauth2.clients.*.openid.issuer`. The same expected issuer is used by api:security.oauth2.ProviderResolver[] to resolve the OpenID client of a token from its `iss` claim.
