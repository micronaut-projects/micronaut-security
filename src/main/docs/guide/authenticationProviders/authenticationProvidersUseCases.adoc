The built-in <<login, Login Controller>> uses every available authentication provider. Providers are evaluated one at a time in precedence order. To control that order, override `getOrder()`: both api:security.authentication.provider.AuthenticationProvider[] and api:security.authentication.provider.ReactiveAuthenticationProvider[] extend api:io.micronaut.core.order.Ordered[], so the `@Order` annotation is ignored and the default order is `0`. The first provider in precedence order that returns a successful authentication response will have its value used as the basis for the JWT token or session state; lower precedence providers are not consulted once a provider accepts the credentials.

Basic authentication which is implemented as an api:security.filters.AuthenticationFetcher[] will also trigger the available api:security.authentication.AuthenticationProvider[]s.
