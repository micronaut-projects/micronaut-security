The module is enabled by default and writes an enforcing `Content-Security-Policy` header in every HTTP Response. It starts from a deny-by-default policy:

* `default-src 'none'`
* `base-uri 'none'`
* `connect-src 'none'`
* `font-src 'none'`
* `object-src 'none'`
* `prefetch-src 'none'`
* `frame-ancestors 'none'`
* `frame-src 'none'`
* `script-src 'nonce-*'`
* `img-src 'none'`
* `manifest-src 'none'`
* `media-src 'none'`
* `style-src 'none'`
* `worker-src 'none'`
* `form-action 'self'`
* `require-trusted-types-for 'script'`

It does not emit `fenced-frame-src` or `report-uri` unless you enable them explicitly.

This baseline intentionally blocks most existing resource loading. Configure only the directives and source expressions required by your application.

Scheme source expressions can be enabled for each source-list directive. They are serialized without single quotes. For example:

[configuration]
----
micronaut:
  security:
    csp:
      img-src:
        data: true
        https: true
----

This configuration generates `img-src https: data:`. The available scheme flags are `http`, `https`, `data`, `blob`, `filesystem`, `mediastream`, `ws`, and `wss`; all default to `false`.
