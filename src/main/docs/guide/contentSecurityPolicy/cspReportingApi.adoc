The CSP module integrates with the <<reporting,Reporting API module>> and can receive Content Security Policy reports. Reporting is disabled by default. Enable the `report-to` directive and select a reporting group:

[configuration]
----
micronaut:
  security:
    csp:
      report-to:
        enabled: true
        group: csp
----

A reporting group is a name that connects a reporting policy to an endpoint declared by the `Reporting-Endpoints` response header. It is not a URL. The group configured above produces `report-to csp`; the same `csp` name identifies the endpoint in `Reporting-Endpoints`.

When `report-to` is enabled and the application also provides an api:security.csp.report.ContentSecurityPolicyReportHandler[] bean, the module registers the controller at `/csp/report` and generates both required response headers. A handler bean alone does not open the route:

[source,http]
----
Reporting-Endpoints: csp="/csp/report"
Content-Security-Policy: default-src 'none'; report-to csp
----

Without a handler, the reporting controller and the module-provided `Reporting-Endpoints` header are not registered. The generated policy can still use `report-to` with an application-managed or external `Reporting-Endpoints` header.

Implement the handler to redact, persist, or forward reports to a monitoring service. Register exactly one handler bean; to send reports to several destinations, delegate from it. The controller calls it on the blocking executor, so it may perform I/O such as a database insert:

snippet::io.micronaut.security.docs.cspreport.ApplicationCspReportHandler[tags="clazz"]

The controller accepts a JSON array with the `application/reports+json` media type and returns HTTP 204 after the handler processes the batch successfully. Reports of other types, such as `deprecation` or `intervention`, can arrive when the reporting group is shared with other policies; the controller skips them and passes only the CSP reports to the handler. A CSP report that is missing a required field, has a field longer than the module's limits, or arrives in a batch of more than 100 reports rejects the whole batch with HTTP 400. These checks run with or without Micronaut Validation. Use a reporting group dedicated to CSP. Its path can be changed with `micronaut.security.csp.report-to.controller.path`. Set `micronaut.security.csp.report-to.controller.enabled=false` to prevent registration even when a handler exists.

The Reporting API envelope contains `age`, `type`, the originating `url`, `user_agent`, and `body`. The body is decoded according to the CSP-defined report type:

* `csp-violation` becomes api:security.csp.report.ContentSecurityPolicyViolationReportBody[].
* `csp-hash` becomes api:security.csp.report.ContentSecurityPolicyHashReportBody[].

The module does not overwrite an application-provided `Reporting-Endpoints` header. When supplying that header yourself, ensure that it declares the same group used by `micronaut.security.csp.report-to.group`. The existing `report-uri` configuration uses the deprecated CSP reporting format and is not a substitute for this Reporting API endpoint.

Reporting endpoints should generally be reachable without authentication because cross-origin report deliveries do not contain credentials. When Micronaut Security is active, permit anonymous POST requests to the endpoint. Adjust the pattern if you changed `micronaut.security.csp.report-to.controller.path`:

[configuration]
----
micronaut:
  security:
    intercept-url-map:
      - pattern: /csp/report
        http-method: POST
        access:
          - isAnonymous()
----

WARNING: The report endpoint is anonymous, so any client can post to it. Browsers send batches of a few kilobytes, but the endpoint accepts bodies up to `micronaut.server.max-request-size` (10MB by default) and the module applies no rate limit. Enforce a small request size limit and a rate limit for the endpoint at your reverse proxy or gateway.

Treat every field as untrusted input. URLs and content samples can contain sensitive data, and content samples can contain attacker-controlled text. Sanitize data before rendering it, and avoid logging complete report bodies without filtering them first.
