
This section will document breaking changes that may happen during milestone or release candidate releases, as well as major releases eg (1.x.x -> 2.x.x).

== Micronaut Security 3.11 breaking changes

- A failed retrieval of a remote JSON Web Key Set (connection error, non-2xx response, unparseable body or a JWK Set without keys) is no longer retried for every token. The JWK Set is not requested again until the back-off configured with `micronaut.security.token.jwt.signatures.jwks-client.failure-backoff` (default 10 seconds) elapses; tokens which cannot be verified by another signature configuration are rejected without contacting the JWKS endpoint. Set the property to `0s` to restore the previous behavior. The retrieval is bounded by `micronaut.security.token.jwt.signatures.jwks-client.retrieval-timeout` (default 30 seconds), applied as the connect and read timeout.

- The constructor `DefaultJwkSetFetcher()` has been deprecated. Use `DefaultJwkSetFetcher(JwksClientConfiguration)` instead.

- api:security.errors.CookiePriorToLoginPersistence[] only stores the path and query of the request rejected prior to login, and only honours a local path (one starting with a single `/`) when redirecting after login. Scheme-relative (`//host/...`) or absolute URIs are ignored and the login handlers fall back to `micronaut.security.redirect.login-success`.

- The plain OAuth 2.0 client (api:security.oauth2.client.DefaultOauthClient[]) now sends the application's own callback URL, built with api:security.oauth2.url.OauthRouteUrlBuilder[], as the `redirect_uri` parameter of the authorization code grant token request. Previously the value stored in the `state` parameter of the authorization response was used, which allowed anyone redirecting the browser to the callback endpoint to choose the `redirect_uri` sent to the provider and redeem an authorization code issued for a different redirection URI (RFC 6749 sections 4.1.3 and 10.6). The OpenID Connect client already behaved this way.

- The constructor `DefaultOauthAuthorizationResponseHandler(TokenEndpointClient, StateValidator, PkcePersistence)` has been deprecated. Use `DefaultOauthAuthorizationResponseHandler(TokenEndpointClient, OauthRouteUrlBuilder, StateValidator, PkcePersistence)` instead.

- The constructor `OauthCodeTokenRequestContext(AuthorizationResponse, SecureEndpoint, OauthClientConfiguration, String)` has been deprecated. Use `OauthCodeTokenRequestContext(AuthorizationResponse, OauthRouteUrlBuilder, SecureEndpoint, OauthClientConfiguration, String)` instead. A context created with the deprecated constructor no longer sends a `redirect_uri` parameter to the token endpoint.

- Single-valued keys directly under `micronaut.security.ldap`, such as the global switch `micronaut.security.ldap.enabled`, no longer create an api:security.ldap.configuration.LdapConfiguration[] named after the key. Previously `micronaut.security.ldap.enabled: true` created a configuration and an api:security.ldap.LdapAuthenticationProvider[] named `enabled` with no server, whose failures turned login attempts for unknown usernames into HTTP 500 responses and allowed username enumeration. Only keys with nested properties, for example `micronaut.security.ldap.default.*`, define LDAP configurations.

- With `micronaut.security.authentication` set to `idtoken`, api:security.oauth2.endpoint.endsession.request.OktaEndSessionEndpoint[] (used for Okta and Oracle Cloud) only sends as `id_token_hint` the token which authenticated the request, as recorded in the request attribute `micronaut.TOKEN` by the token authentication fetcher. Previously, it sent the first token found in the request, which could be an unrelated `Authorization: Bearer` header added by a gateway rather than the ID token cookie. If no token authenticated the request and the authentication has no `openIdToken` attribute, no `id_token_hint` is sent.

- Starting with 3.11.3, api:security.oauth2.endpoint.token.response.validation.IssuerClaimValidator[] requires the `iss` claim of an ID token to match the issuer expected for the OpenID client in addition to the Issuer Identifier of the provider metadata. The expected issuer is `micronaut.security.oauth2.clients.*.openid.issuer`, or `micronaut.security.oauth2.clients.*.openid.issuer-identifier` when set. The comparison is exact, tolerating only the case of the scheme and a trailing slash. Moreover, an `issuer` announced in the provider's discovery document that does not match the expected issuer is discarded (an error is logged) and the expected issuer is used instead, as required by OpenID Connect Discovery 1.0 section 4.3. ID tokens whose `iss` claim only matched the issuer announced by the provider are now rejected. If the provider issues tokens with an `iss` that differs from the URL used to fetch the discovery document (for example, discovery over a cluster-internal URL, or Oracle IDCS with a tenant specific `issuer` and the provider wide issuer `https://identity.oraclecloud.com/`), set `micronaut.security.oauth2.clients.*.openid.issuer-identifier` to the expected `iss` value.

==== Other Changes

- The api:security.event.LoginSuccessfulEvent[] that gets emitted when a user logs in will now be created with an instance of api:security.authentication.Authentication[].
- The `AuthenticationUserDetailsAdapter` class has been deleted.

=== SecurityRule Changes

The api:security.rules.SecurityRule[] API has changed. The last argument to the method was a map that represented the user attributes. Instead that argument was replaced with a reference to the api:security.authentication.Authentication[]. This has the benefit of rules now having access to the username of the logged in user as well as access to the convenience method `getRoles()`.

In addition, the return type of the method has changed to return a `Publisher`. This was necessary because the security rules execute as part of the security filter which may be on a non blocking thread. Because the method now returns a `Publisher`, blocking operations can be offloaded to another thread pool using the reactive streams implementation of your choice.

Micronaut 2 API:

`SecurityRuleResult check(HttpRequest<?> request, @Nullable RouteMatch<?> routeMatch, @Nullable Map<String, Object> claims);`

Micronaut 3 API:

`Publisher<SecurityRuleResult> check(HttpRequest<?> request, @Nullable RouteMatch<?> routeMatch, @Nullable Authentication authentication);`

=== LDAP Package Change

All classes in the `io.micronaut.configuration.security.ldap` have been moved to the `io.micronaut.security.ldap` package.

=== SecurityFilter

The security filter no longer extends deprecated `OncePerRequestHttpServerFilter` because it has been deprecated in Micronaut 3.

=== Cookie Secure Configuration

The following properties' default value has been removed in Micronaut Security 3.0.0:

- `micronaut.security.oauth2.openid.nonce.cookie.cookie-secure`
- `micronaut.security.oauth2.state.cookie.cookie-secure`
- `micronaut.security.token.jwt.cookie.cookie-secure`
- `micronaut.security.token.refresh.cookie.cookie-secure``

NOTE: If the `cookie-secure` setting is not set, cookies will be secure if the request is determined to be HTTPS.

=== Deprecations Removal

Most if not all deprecated classes constructors, and methods have been removed.

=== Other Changes

- The constructor of api:security.token.jwt.validator.DefaultJwtAuthenticationFactory[] has changed
- The constructor of api:security.oauth2.endpoint.token.response.IdTokenLoginHandler[] has changed
- The constructor of api:security.session.SessionLoginHandler[] has changed
- The constructor of api:security.authentication.BasicAuthAuthenticationFetcher[] has changed
- The api:io.micronaut.security.token.RolesFinder[] method `findInClaims` has been deprecated and usages should be replaced with `resolveRoles(@Nullable Map<String, Object> attributes)`.
