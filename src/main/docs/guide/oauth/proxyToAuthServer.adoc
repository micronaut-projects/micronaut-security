You can proxy GET requests to `/.well-known/oauth-authorization-server` https://datatracker.ietf.org/doc/html/rfc8414[RFC8414]
and `/.well-known/openid-configuration` https://openid.net/specs/openid-connect-discovery-1_0.html[Open ID Connect Discovery] to an authorization server.

image::proxy.svg[]

To proxy set the following configuration properties to `true`:

|===
|Path to proxy | Property
| `/.well-known/oauth-authorization-server`
| `micronaut.security.oauth2.clients.*.proxy-well-known-oauth-authorization-server`
| `/.well-known/openid-configuration`
| `micronaut.security.oauth2.clients.*.proxy-well-known-openid-configuration`
|===

The request sent to the authorization server is a fresh `GET` for the well-known path at the issuer's origin: headers (such as `Cookie` or `Authorization`), cookies and the query string of the incoming request are not forwarded.

Only a successful (`2xx`) JSON response from the authorization server is relayed to the caller, and only its `Content-Type`, `Content-Length`, `Cache-Control`, `Expires`, `ETag` and `Last-Modified` headers are copied; every other header, notably `Set-Cookie`, is dropped and `X-Content-Type-Options: nosniff` is added. Any other response from the authorization server (an error status or a non-JSON body) is answered with `502 Bad Gateway` and an empty body.

Anonymous access is granted only to the well-known paths which are actually proxied. A well-known path whose proxy property is `false` is secured as any other route of your application.
