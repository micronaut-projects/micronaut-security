The authorization code grant flow is the most typical authentication flow with OAuth 2.0 and OpenID providers. The same main steps apply to the flow whether or not the provider supports OpenID, and is described in link:https://tools.ietf.org/html/rfc6749#section-4.1[RFC6749 - Authorization Code Grant].

The OAuth 2.0 authorization code flow requires a callback endpoint. In addition, a login endpoint is available to trigger the flow. The URIs are configurable.

include::{includedir}configurationProperties/io.micronaut.security.oauth2.configuration.OauthConfigurationProperties.adoc[]

The URI templates for login and callback have a template variable in them `{provider}`. That variable is used by the route builder to build routes for each provider that is configured. The name `provider` is special in this context and cannot be changed. The URI may be manipulated however in any way as long as the provider variable is part of the *path* of the URI.

For example `/oauth/login{?provider}` is not a valid configuration because Micronaut does not consider the query segment of a URL when routing requests. The provider variable must be part of the *path*.

TIP: It is possible to designate a default provider. The value of the configuration must match one of the client names. The default provider will have the same uri template, but with `null` passed as the provider parameter. By default that will result in `/oauth/login` being redirected to the default provider authentication page.

#### OAuth Login and CSRF

Any site can link to, or redirect the browser to, the login endpoint. If the user has a session at the identity provider and has already authorized the application, the provider redirects back at once and the user is logged in to the application without intending to (forced login). The `state` parameter checked by the callback does not prevent this, because the browser that started the flow is the one that completes it.

The recommended protection is the <<fetchMetadata,Fetch Metadata>> module. The login endpoints are annotated with api:security.fetchmetadata.DenyCrossSiteNavigation[], so, with the module installed, a navigation to them that a web page of another site started is rejected with `403 Forbidden`, while a login started from the application itself keeps working. Logins started from the identity provider's dashboard, or from a link on another origin of the same site, are rejected too. See <<fetchMetadataSensitiveNavigationRoutes,Routes Closed to Cross-Site Navigation>> for the details and the caveats.

dependency:micronaut-security-fetch-metadata[groupId=io.micronaut.security]

The module applies its resource isolation policy to every route, not only the login route. For example, it also rejects cross-site form `POST` callbacks such as `response_mode=form_post`. Review <<fetchMetadataInstallation,Installation>> before enabling it.

The login response is marked `Cache-Control: no-store`, unless the api:security.oauth2.client.OauthClient[] sets a `Cache-Control` header itself.

If you do not use the Fetch Metadata module, you must implement CSRF protection on the OAuth login endpoints yourself. Because this library is not in control of the forms where login may originate from, we cannot ensure that CSRF is applied. In addition, there is no sensible defaults with regards to how the token is stored or how it should be retrieved. Implementing CSRF is relatively simple.

1. When rendering the login form where users can choose to login via OAuth, the server should store a value either in state on the server specific to that user (session), or state on the client (http-only cookies, etc), or some other mechanism.
2. That value gets sent with the response and subsequently included in the request to login with OAuth. The value could be sent as a query parameter, or sent as a cookie, etc.
3. A server filter is written to compare the value in the user specific state and the value sent in the request. If they do not match, the request is rejected. Compare the values in constant time, so that the response time does not reveal the expected value.
