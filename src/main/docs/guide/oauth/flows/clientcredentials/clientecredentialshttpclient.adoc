Micronaut Security includes api:security.oauth2.client.clientcredentials.propagation.ClientCredentialsHttpClientFilter[]. This https://docs.micronaut.io/latest/guide/index.html#clientFilter[HTTP Client Filter] allows you to automatically include an access token to an outgoing request HTTP Header. It obtains the access token via a Client Credentials request.

For example, the next configuration adds an access token to the requests' HTTP Headers done via the HTTP Client `inventory`. It obtains the access token with a Client Credentials request with the OAuth 2.0 client `companyauthserver`.

[configuration]
----
micronaut:
  security:
    oauth2:
      clients:
        companyauthserver:
          client-id: 'XXX'
          client-secret: 'YYY'
          client-credentials:
            service-id-regex: 'inventory'
          token:
            url: "https://foo.bar/token"
            auth-method: client_secret_basic
----

The access token is cached per scope until it expires. Its expiration is computed once, when the token response is received:

. from the token response `expires_in` parameter, if present;
. otherwise, from the `exp` claim, if the access token is a JWT;
. otherwise, the token is cached for `client-credentials.default-expiration` (5 minutes by default).

A cached token is considered expired `client-credentials.advanced-expiration` (30 seconds by default) before its expiration. Set `default-expiration` to a value greater than `advanced-expiration` when your authorization server issues opaque tokens without `expires_in`.

[configuration]
----
micronaut:
  security:
    oauth2:
      clients:
        companyauthserver:
          client-credentials:
            default-expiration: 10m
----

Access token values are never logged. At `TRACE` level only a short SHA-256 prefix of the token and its expiration are logged.
